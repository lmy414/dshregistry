DSH Capability Inspector

English | 简体中文

A read-only runtime diagnostics and health-check plugin for DeepSeek Harness.

DSH Capability Inspector registers an inspect_dsh tool that explains which capabilities are actually available to the calling agent and where a configuration or runtime problem may be occurring.

It is also useful when searching for a DeepSeek Harness Doctor, DSH diagnostics, DSH capability matrix, plugin readiness checker, or MCP troubleshooting tool.

What it checks

  • Node.js version, operating system, architecture, and working directory
  • Tools visible in the calling agent's scope
  • LLM providers and their model catalogs
  • Skills, providers, and invocation modes
  • Workspaces, directory status, and associated session counts
  • Session persistence availability
  • Missing capabilities and per-check errors

The plugin never returns API keys or other credential values. It does not change configuration and does not automatically repair failures.

Install

From GitHub

dsh plugin --profile web add github:tree201/dsh-capability-inspector
dsh web

DeepSeek Harness is currently in developer preview. If pnpm asks for build-script authorization during a Git install, review the DSH plugin installation guidance and only authorize source you trust.

From a local checkout

dsh plugin --profile web add /absolute/path/to/dsh-capability-inspector
dsh web

Use

After restarting DSH, ask the agent:

Inspect the current DSH runtime and summarize available capabilities and warnings.

More focused prompts also work:

List the tools and skills available to this agent.

Check model providers and model catalogs.

Check workspace and session persistence health.

The agent can call inspect_dsh with one of these scopes:

  • summary — full report; the default
  • tools — scoped tool catalog
  • models — providers and model catalogs
  • skills — skill catalog
  • workspaces — registered workspace health
  • sessions — session persistence health

Design boundaries

The first release uses supported, read-only DeepSeek Harness enumeration APIs.

  • It does not inspect private Cordis reflection state.
  • It does not expose credential values.
  • One failed provider or capability check does not fail the whole report.
  • It cannot inspect a plugin that failed before this plugin loaded.
  • It reports problems but does not automatically fix them.
