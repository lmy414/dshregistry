状态联动

情绪读自两个来源：shell.overlay 标准 prop useSessions（会话列表：谁在跑、谁在等你），以及当前会话的对话装配——插件自己用客户端 sessions 服务把 sessions.binding(current).session 的 ConversationSnapshot 订阅下来。同步率每 0.9s 向目标值收敛：

情绪 触发 目标同步率 HUD
IDLE 其余 60 UMBILICAL LINKED / TOOL n
ACTIVE 当前会话 running，或存在任意 running 会话 88 ACT n / TOOL n
STANDBY 当前会话有 pendingInteraction（等你授权/回答） 71 —
OPERATE 当前会话有正在执行的工具调用 94 OP <工具名>
ALERT 当前会话出现新的 agent 错误 33 ⚠ PATTERN BLUE ×n
BERSERK 双击 400 PWR mm:ss

优先级：BERSERK > ALERT > OPERATE > ACTIVE > STANDBY > IDLE。

派生规则（readFeed）：

  • TOOL n —— 窗口内 tool-result 节点数 + 当前在跑的调用数。
  • ⚠ PATTERN BLUE ×n —— 失败的 tool-result（isError）与 turn-error 节点计为「使徒」。
  • ALERT —— 由 lastAgentError 文本变化驱动，警报持续 8 秒后自动解除并播报「使徒歼灭」。订阅建立时读到的那条错误只作基线，不报警，所以刷新页面不会为历史失败拉响警报。
  • 流式 token 不触发重算：feedSig 只在节点数、在跑调用、错误文本变化时才重新折叠快照。

设计说明：为什么不走宿主事件

早期动态插件版本用宿主 agent/error 与 tools/result 事件驱动 ALERT 与 TOOL 计数。常驻插件的 浏览器半程没有动态包那种 Package 私有 host.call 通道，而 @deepseek-ai/dsh-api-remotes 的转发 白名单（API_REMOTE_FORWARDED_EVENTS）是构建时固定的、不含这两条事件——不改动 deployment 自带的 安装就加不进去。

但这两项能力不需要宿主通道：浏览器本来就持有当前会话的完整装配。ConversationSnapshot 直接带 nodes（含 tool-result / turn-error）、runningCalls 与 lastAgentError，所以改成从客户端 快照派生，反而比事件驱动更好：

  • 刷新页面后计数不丢（快照是权威，不依赖曾经收到过哪条事件）；
  • 能显示当前正在执行的工具名，事件计数做不到；
  • 零宿主侧改动，宿主半程仍是空 apply。

代价：计数限于当前加载窗口内的节点（loadOlder 之前的历史不计入）。

用户要的是真音：任务处理、点击、完成提醒都用初号机自己的音效/音乐，而不是听起来"像"的合成音。 本轮加的是采样层，不是替换掉合成器——两者同时在线，文件有就用文件，没有就用合成。

1. 宿主半程第一次有了行为

lib/index.js 以前是空 apply（纯浏览器插件）。现在它注册一条只读路由，因为浏览器自己读不了磁盘：

路由 作用
GET /eva01-audio/manifest 返回 { dir, writable, files:[{name,bytes,type}] }
GET /eva01-audio/file/<name> 返回单个文件的字节（content-type 按扩展名，缓存 300s）

没有上传路由，这是故意的：文件由用户用资源管理器放，页面侧写不了任何东西。安全性是实测过的： resolveAudio 只认"出现在目录列表里的纯文件名"，所以 ../../settings.yaml、 ..\\..\\settings.yaml、sub/click.mp3、.、空串、非音频的 notes.txt 全部返回 undefined （逐个跑过）；apply() 在没有 webServer 服务时静默返回，不抛。

投放目录：%USERPROFILE%\.dsh\eva01-audio（可用环境变量 EVA01_AUDIO_DIR 覆盖）， 首次读 manifest 时自动创建；已在里面放了一份 放这里.txt 说明。

2. 文件名决定它替换哪个事件

文件名 替换 事件
click.* blip 单击桌宠
task-start.* / start.* up 开始处理任务（进入 ACTIVE）
task-done.* / done.* / complete.* taskdone 任务完成提醒（回到 IDLE）
alert.* alarm 使徒警报（出现错误）
berserk.* roar 双击暴走
bgm.* / music.* —— 任务处理期间循环播放的音乐

进阶：文件名等于任意一个内置 kind（现有 50 个）就覆盖那个 kind —— 放个 atfield.mp3， A.T. 力场展开就用你的文件，其余仍走合成。

3. 工程细节

  • 采样播放挂在 playSfx 里、节流检查之后、合成层循环之前：采样同样受 THROTTLE 约束 （不会连发），命中采样时一个合成节点都不建。
  • 首次触发某个 kind 时缓冲区还在解码（decodeAudioData 是异步的），那一次仍由合成音应答， 之后都是真音。BGM 会在 1.2s 后重试一次，避免开局那一次错过就整场没音乐。
  • 增益：音效 SAMPLE_GAIN 0.5、音乐 BGM_GAIN 0.2，音乐永远压在音效之下；淡入 0.6s、 淡出 0.7s；♪ 静音开关会一并停掉音乐；active ↔ tool 切换不会重启音乐（effect 故意不写 cleanup），卸载时停。
  • 插件不附带任何音频资源：包体积没变，仓库里没有一个音频文件。

4. 新闸门 audit-samples.cjs 第一次运行就抓到一个真 bug

这道审计断言 5 条：槽位目标必须是真实 kind、bgm/music 不能同时是 kind、采样钩子必须在节流之后 合成之前、BGM_GAIN < SAMPLE_GAIN ≤ 1、两个半程的路由常量必须对齐。

第一次跑就红了：SAMPLE_ALIAS.berserk 指向 "growl"，而 growl 只是 SFX_ALIAS 里 roar 的历史别名。playSfx 先解析别名再查采样表，所以采样表的键必须是解析后的 kind —— 照原样发出去，berserk.mp3 永远不会响。改为 "roar"，并给审计加了一条"槽位不得指向别名"的断言。
