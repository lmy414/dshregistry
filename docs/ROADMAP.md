# DSH-Registry 开发路线图(索引深化)

> 状态:规划(2026-08-16)。定位:把"索引"做深——**可发现性(找得到)、数据质量(找得准)、新鲜度(不陈旧)、可信度(敢用)**。

## 现状(已完成)

- 基础展示:2207 个收录插件的真实索引;首页(搜索/分类/排序/分页「加载更多」)/ 详情页(完整 README 渲染)/ 关于 / 404
- 数据管道:增量爬虫(topic 扫描 + Issue 提交通道收录;已收录清单跳过;每轮 ≤300 新仓库;jsDelivr 内容通道;README 消毒渲染;slug 唯一化;原子写)
- 信任体系:三态徽章(未审计/社区认可/有风险报告);200★ 高牵引豁免作者年龄;依据 ✓/✗ 可见;flags.json 人工覆盖
- 提交:Issue 表单收录(无需 fork);中英双语 + 明暗主题 + 响应式

## P0 · 索引核心(近期)

### 1. 搜索覆盖 README 全文
- **问题**:搜索只匹配名称/描述;功能词往往只出现在 README;2207 个片段 ~20MB 无法前端全量加载。
- **方案**:爬虫构建轻量 `web/data/search.json`(每插件:名称/描述/tags + README 关键词抽取:标题、加粗词、代码块、前 N 字),前端本地索引即时搜索;随爬虫增量更新。
- **验收**:输入仅存在于 README 的功能词能命中;`search.json` < 5MB。

### 2. 已收录仓库的新鲜度跟踪
- **问题**:增量只收新仓库;已收录插件的 commit pin / 描述会过期(安装命令锁的是旧 commit)。
- **方案**:每轮增量后追加"活跃更新窗口"——按 `pushedAt` 取已收录前 200 个,校验变化重抓(复用 pkgCache 的 pushedAt 机制);变化者更新 latestCommit/描述/片段。
- **验收**:重跑后活跃插件的 `latestCommit` 更新,不活跃的零成本跳过。

### 3. 分类推断加强
- **问题**:`other` 占 1059/2207(48%),推断过弱。
- **方案**:扩充关键词库(README 标题/描述提取);`dsh.registry.category` 优先;站长维护 `config/categories.json` 人工覆盖(owner/repo → 分类)。
- **验收**:`other` 占比降到 <25%。

## P1 · 发现性(中期)

- **4. 标签筛选**:分类之外加 tags 筛选 + tags 云;详情页展示 tags。
- **5. 相关推荐改进**:由"同分类随机 4 个"改为 tags 重叠度 + stars 加权。
- **6. 首页发现区块**:最新收录 / 本周最热 / 高星精选(数据来自 meta/plugins 的 pushedAt、firstSeenAt、stars)。
- **7. 本地收藏**:localStorage 收藏,v1 无账号的本地方案;首页"我的收藏"视图。

## P2 · 质量与治理(远期)

- **8. 数据质量 CI**:仓库 GitHub Actions——推送时校验 `plugins.json`(schema/唯一性/必填字段);每周死链扫描(仓库 404、片段缺失)。
- **9. 收录历史可见**:详情页展示该插件的收录/更新事件线(爬虫在 meta.json 追加 changelog,或从 crawl commit message 提取)。
- **10. SEO / 无 JS 可读**:详情页预渲染静态 HTML 或至少补 meta description(当前为 JS 渲染,对搜索引擎不友好)。
- **11. 数据契约版本化**:`plugins.json` 加 `schemaVersion`,客户端按版本兼容。

## 明确不做(维持 v1 架构边界)

- 后端 / 账号 / 在线安装统计(无 HTTP API 架构不变;安装即 `dsh plugin add` 命令行)
- 在线举报(保持 Issue 通道)
- 自动审核(信任判定规则后续单独迭代,见 `tools/crawl.js` 的 `computeState`)
