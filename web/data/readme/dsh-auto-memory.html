dsh-auto-memory

DeepSeek Harness (DSH) 的会话级记忆插件：自动收尾提醒、记忆索引维护、实时对话日志、LLM 摘要压缩。所有配置都在「设置 → 插件 → AutoMemory」，无需手改 YAML。

dsh-auto-memory 让 DSH 记住你真正关心的东西：会话结束时有条理地收尾，跨会话的决策和结论不再丢失，旧对话自动沉淀成可检索的日志。

特性

  • 收尾提醒：会话开始时把项目记忆索引注入给模型，超出行数/大小软上限时主动提醒整理
  • 记忆索引：项目根 MEMORY.md 一行一个主题，配合笔记库（memory/）承载详细内容
  • 实时对话日志：会话过程中持续提取关键内容到 now.md，结束后归档为 today-YYYY-MM-DD.md 每日日志
  • LLM 摘要压缩：历史日志可用独立配置的摘要模型压缩进 recent.md（默认关闭，保留原文）
  • 摘要模型独立可选：在「设置 → 模型」添加任意 OpenAI 兼容提供方（含本地 Ollama / LM Studio），摘要用它不改变主模型
  • 全图形化配置：无需手改 YAML，面板开关/下拉/文本字段直接读写

安装

要求：DSH（DeepSeek Harness）、Node.js 20+。peer 依赖由 DSH 运行时提供（@deepseek-ai/cordis、@deepseek-ai/schemastery、@deepseek-ai/dsh-settings）。

dsh plugin --profile web add <仓库地址或本地目录>

安装后重启 DSH，在「设置 → 插件」找到 AutoMemory。

配置

分组 字段 默认 说明
会话记忆整理 启用会话提醒 开 注入记忆索引并做收尾提醒
记忆索引文件 MEMORY.md 项目根索引文件名
状态目录 .dsh 收尾标记存放目录
索引行数上限 150 超过后提醒整理
索引大小上限 20 KB 超过后提醒整理
会话日志 启用对话日志 开 实时记录会话日志
日志目录 .remember 项目根下日志目录
摘要提供方 空 压缩历史日志用的提供方；空=跟随当前会话模型
摘要模型 空 从所选提供方的模型目录中选择
摘要长度 3000 单次摘要最大 token 数
会话结束归档压缩 关 开启后把旧日志压成摘要存入 recent.md 并删除原文

摘要模型

在「设置 → 模型 → 添加提供方」添加 OpenAI 兼容端点（官方或本地均可），它即出现在「摘要提供方」下拉。摘要使用独立模型，不会改变当前会话的主模型；留空则摘要跟随当前会话模型。

工作原理

会话开始 ── 注入 MEMORY.md 索引 + 检查软上限（超限提醒整理）
会话进行 ── 实时提取关键内容 → .remember/now.md
会话结束 ── 归档 now.md → today-YYYY-MM-DD.md
            ├─（可选，默认关）历史日志 LLM 摘要 → recent.md，删除原文
            └─ 写收尾标记 → .dsh/auto-memory-done
  • 收尾 skill 自动复制到 ~/.dsh/skills/auto-memory，指导收尾时该提炼什么
  • 摘要模型独立配置，避免占用主模型额度；支持本地便宜模型

目录结构

├── lib/index.js          Host 端（Cordis 插件）：记忆生命周期、LLM 摘要、HTTP 配置路由
├── lib/client.js         Client 端（浏览器 bundle）：设置面板，经 /auto-memory/api 读写配置
├── cordis.patch.yml      bundle patch：声明 Host 依赖（llm / settings / webServer）
├── scaffold/             项目记忆脚手架（MEMORY.md 索引 + 笔记模板）
└── skills/auto-memory    收尾 skill 模板

常见问题

摘要模型下拉是空的？ 先在「设置 → 模型」添加提供方（官方端点或本地 OpenAI 兼容服务），重启后下拉即列出该提供方的模型目录。

面板不显示？ 浏览器硬刷新（Ctrl+Shift+R）；确认安装后已重启 DSH。
